# 知行个人 Android APK 客户端设计

> 状态：页面级 UI/UX、品牌视觉、Git/安全边界与 Android 工程参数已于 2026-08-03 获用户批准；等待按独立计划完成地基执行。  
> 范围：只定义离线固定样例阶段的客户端与接口边界；不实现真实数据、密钥、云端调度或生产 APK 发布。

## 1. 目标与非目标

目标是在 Android 真机上提供一个可安装的“知行”客户端，能安全地展示固定样例报告，验证手机端的阅读、归档、分类与应用外壳体验，并为未来可信云端报告引擎预留明确接口。

本切片不做：真实 iFind 调用、交易日历、模型、用户注册、多人使用、云端调度、真实 PDF、公开下载页、APK 正式签名分发或 iOS。

## 2. 技术选择

采用 React + TypeScript + Vite 构建静态 Web 客户端，由 Capacitor 8 封装为 Android APK。

- 优点：复用 TypeScript、HTML、CSS 与既有报告视觉规范；Android 真机可以安装和验证；未来仍可复用客户端界面。
- 约束：APK 内只能包含静态界面与固定夹具，不能把服务端密钥、真实数据源 SDK 或管理能力打进包内。
- 不采用原生 Kotlin/Flutter：当前没有摄像头、蓝牙、复杂离线同步等必须原生实现的能力，重写界面没有收益。
- 客户端目录固定为 `client-app/`，应用显示名为“知行”，应用 ID 为 `com.zhixing.research`。
- 使用 React Router Hash 路由；首切片只使用 React 内置状态与仓库接口，不引入全局状态库。
- Android 参数为 `minSdk 24 / compileSdk 36 / targetSdk 36`；工程初始化和日常开发先使用单一 API 36 模拟器，首个调试 APK 完成前仍须保留真机最终验收。
- 首个产物只允许调试 APK，不创建正式签名证书。
- 完整的版本控制、安全和工具链决策见 `2026-08-03-client-engineering-preflight-decisions.md`。

## 3. 组件边界

```text
Android APK
  ├─ AppShell：导航、主题、版本与网络状态提示
  ├─ FixtureReportRepository：读取本地固定报告夹具
  ├─ Screens：今日报告、报告库、详情、产业与标的池、个人操作页
  └─ FutureApiClient：仅定义未来接口类型，本切片不发网络请求

未来可信服务端
  ├─ OwnerAuth：验证单一所有者身份
  ├─ ReportReadApi：只读已归档报告 / PDF 下载授权
  ├─ OwnerActionApi：受限的刷新和失败重试请求
  └─ ReportEngine：交易日历、数据适配器、证据、生成、校验与归档
```

APK 与未来服务端通过类型明确的 API 边界连接；在离线切片中，`FixtureReportRepository` 是唯一数据实现，`FutureApiClient` 不得发起网络请求。

正式页面地图、建议路由、共享组件边界和工程验收清单见 `docs/ui-ux/client-ui-ux-handoff.md`；逐页 HTML/PNG 见 `docs/ui-ux/README.md`。工程实现不得以 `.superpowers/brainstorm/` 临时讨论稿为依据。

品牌方向、App 图标、Android 启动页和统一设计 Token 见 `docs/superpowers/specs/2026-08-03-brand-visual-foundation-design.md`。工程实现必须使用该规范的单一 Token 体系，但不得借视觉统一改变已确认页面的信息结构和交互。

## 4. 页面与交互

### 今日报告

- 默认页，采用 B2 纯阅读优先；主卡优先继续未完成阅读，没有未完成阅读时展示最新报告。
- 核心摘要只汇总当日已经生成的报告，不为未生成或失败内容补写摘要。
- 早盘、午间、每日复盘、行业跟踪四张日常卡位置固定；卡片显示日期、版本、数据截至时间、阅读与任务状态。
- 周末/节假日和月末等周期报告在四张日常卡下方使用动态区域，有内容才出现，没有内容时整块隐藏。
- 异常不占据首页顶部；对应卡显示延迟/失败，完整原因与受控重试入口进入“我的”。
- 点击报告进入统一详情；无可用样例时使用原因明确的空状态，不伪造内容。

### 报告库

- 使用本地夹具提供搜索以及日期、类型、行业/主题组合筛选。
- 默认按日期倒序；结果进入详情。

### 报告详情

- 使用既有受控 HTML 渲染器输出；保持移动端信息卡片、风险提示和版本信息。
- PDF 按钮在离线切片中显示“当前不可用”；不得生成伪 PDF 或空下载。

### 产业与标的池

- 展示行业跟踪固定样例与只读的标的池占位状态。
- 真实 `watchlist_snapshot` 尚未实现时，不能从报告正文自动推断标的。

### 个人操作页

- 展示所有者访问状态、最后同步时间、今日任务摘要、本机 PDF/缓存、脱敏诊断和客户端版本。
- 刷新只代表同步索引、状态和归档，不触发重新生成报告。
- 失败任务先显示简明原因，再确认重试；未来必须复用服务端幂等标识。
- “刷新”“重试”“检查更新”在离线切片中应禁用并说明需要未来可信服务端；不得模拟成功。

## 5. 安全与失败语义

- 状态分为页面级、区块级和操作级，只影响真实受阻范围；局部失败不得无条件替换整页。
- 状态优先级为：所有者访问/安全阻断 ＞ 无可用内容的失败 ＞ 离线无缓存 ＞ 加载 ＞ 空内容。离线但有缓存、同步失败但有旧内容时，保留阅读并叠加非阻断提示。
- 正常内容固定展示数据截至时间、版本和最后同步时间；旧内容必须标注“可能已过期”和最后成功时间。
- 首次加载保留页面标题、导航与最终布局一致的骨架；短于约 300ms 不闪骨架，超过 10s 提示加载较慢但不自动宣告失败。
- 空状态必须区分未到生成时间、当天无报告、筛选无结果及暂无历史/标的，并只提供与原因匹配的真实操作。
- 没有任何可用内容且读取失败时显示页面级失败；只展示脱敏错误码、时间和允许的恢复动作。
- 离线且有缓存时继续提供只读内容，禁用刷新、重试和未缓存下载；离线无缓存时不得回退到演示数据。
- 客户端只在在线且错误可重试时提供手动重试，复用幂等标识，不执行无限自动重试。
- 状态不能只依赖颜色表达；必须同时使用文字和图标，并尊重系统“减少动态效果”设置。
- APK 不含任何 Token、API Key、管理员口令、真实报告或敏感用户数据。
- 离线数据读取失败时，显示本地错误状态，不回退到网络或生成内容。
- 无报告类型、非法夹具、未通过既有报告校验的内容必须被拒绝。
- 未来网络接口未配置时，客户端禁止请求；不得使用硬编码地址或隐式测试服务器。

完整决策与视觉参考见 `docs/ui-ux/decision-forms/cross-page-states-v1.md`、`docs/ui-ux/screens/cross-page-states.html` 和 `docs/ui-ux/screens/cross-page-states.png`。

## 6. 验收标准

1. Android APK 可在一台真机或模拟器安装并启动；
2. 已确认的核心页面、详情页与通用状态可导航，且 390px 宽度无横向滚动；
3. 固定样例报告可在客户端内阅读，视觉与现有 HTML 规范一致；
4. 所有未来服务端操作均处于禁用/明确未配置状态；
5. 应用包、源代码与运行日志中不存在真实密钥、网络地址或真实市场数据；
6. 项目现有 `report-engine` 测试仍全部通过。

## 7. 拆分顺序

1. 建立 Android 客户端工程与 Capacitor 配置；
2. 接入固定报告夹具和导航壳；
3. 完成已确认页面与正常、加载、空、失败、离线通用状态；
4. 构建调试 APK，在真机/模拟器验证安装和阅读；
5. 运行既有报告引擎回归测试与客户端静态检查；
6. 记录验证结果；真实数据和云端能力留待独立设计。
