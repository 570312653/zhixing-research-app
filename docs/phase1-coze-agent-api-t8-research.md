# 知行 Phase 1：Coze Agent API T8 官方行为核验

> 核验日期：2026-07-21  
> 范围：隔离 Coze Coding Agent POC 的 API 行为；不包含真实报告、用户数据、限流压测或凭证操作。

## 已由官方文档核验

官方《[通过 API 调用智能体](https://docs.coze.cn/dev_how_to_guides_qeesmmos)》明确列出：

- `POST /stream_run` 用于直接调用智能体并通过 SSE 持续接收回复、工具调用等事件；当前 POC 已实际使用该路径。
- `POST /async_run` 面向执行时间较长且不需要在当前请求立即取得结果的场景；提交后先返回异步任务 ID。
- `/task/{task_id}` 用于按异步任务 ID 查询任务状态、执行结果或错误信息。本文档未在本次核验中确认该查询路径的具体 HTTP 方法，正式接入前必须以部署页示例为准。
- 异步任务默认最长运行 24 小时，实际截止时间以接口返回的 `deadline` 为准。
- 异步任务依赖当前部署对应的沙箱实例：重新部署会终止其中正在运行的异步任务；实例约 1 小时未收到请求可能被回收。官方建议对需要保活的异步任务持续轮询状态。
- 任务可能长时间处于 `pending`；官方说明这通常代表任务尚未被系统接纳，并建议重新提交。

## 未核验或未在官方页面找到的能力

- 未找到适用于该 Coze Coding Agent API 的明确限流配额或并发上限；不得根据本次 3 次成功调用推导容量。
- 未找到异步任务的取消接口或取消语义；正式方案不得假设存在取消能力。
- 未对 `/async_run` 做真实调用、任务轮询或故意超时测试；因此异步请求/响应字段、状态枚举、实际 deadline、错误语义仍未通过本项目实测。

## T8 结论

T8 的“平台官方行为记录”已部分完成：正式归档报告应优先使用 `/async_run + /task/{task_id}`，而不是把当前 `/stream_run` POC 直接升级为生产链路。

为避免无目的压测，本阶段不主动触发限流、超时或实例回收。下一阶段若继续评估 Agent API，需在独立 POC 中使用固定测试内容依次验证：异步提交、轮询、`pending` 超时策略、`deadline`、重部署中断处理以及应用侧退避重试。
