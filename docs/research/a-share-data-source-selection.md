# A 股主数据源选型研究

> 研究日期：2026-07-31  
> 范围：面向 5–10 名受邀用户的、非个人化市场研究报告；不用于交易、下单或个性化投资建议。  
> 结论性质：本文件只依据供应商公开的第一方资料做初筛，**不是采购、授权或合规结论**。任何真实调用、密钥配置和上线仍须单独审批。

## 1. 先说结论

若只能选一个 A 股主数据供应商，当前建议把 **Wind（万得）** 放在第一优先级，发起企业采购与授权确认；同时把 **东方财富 Choice**、**同花顺 iFinD** 作为同级商业备选，一起询价和做受控 POC。

原因不是“某个 API 更容易调”，而是本项目的硬需求同时包括：A 股覆盖、盘中时效、长期稳定、企业级支持，以及能向受邀用户展示由数据加工而来的研究结论。Wind 的官方资料公开说明了 Client API、A 股/全球公司与行业数据、历史日线/Tick/分钟数据、快速行情和专业运维能力，因此最接近这一组合要求。[Wind Client API](https://www.wind.com.cn/mobile/ClientApi/zh.html)

不过，三家公开页面都**没有替代正式合同**来确认“Web 服务端调用、向 5–10 位受邀用户展示衍生报告、保留归档、展示来源、是否允许实时行情”的全部权利。因此，最终应以书面授权范围、SLA、实际时延和报价决定，不应因为能申请试用或能跑通 SDK 就直接上线。

## 2. 本项目需要的不是单一“数据”，而是两类能力

| 报告环节 | 需要的能力 | 对时效的要求 | 建议的来源角色 |
| --- | --- | --- | --- |
| 午盘扫描 | A 股指数、行业、个股、成交与异动事实 | 盘中；必须在合同中明确实时/延时级别 | **商业主行情源** |
| 日终复盘 | 收盘行情、成交、涨跌停、资金/行业/公告事实 | 收盘后稳定可得；需数据截至时间 | **商业主行情源** |
| 行业总览 | 行业指标、财务、公告、宏观与长期历史序列 | 日内或日终均可，重点是口径稳定与可追溯 | **商业主数据源 + 研究证据补充** |
| 早盘扫描 | 海外市场、期货、宏观和重要新闻 | A 股开盘前 | 海外数据源/新闻证据源，不是 A 股主行情源的替代物 |

所以推荐结构是：**一个有正式商业合同的 A 股主行情/基本面源**，再配一个用于公告、新闻和研究线索发现的补充证据源；不能把“搜索到的文本”当作盘中行情的权威来源。

## 3. 结论分级

| 平台 | 技术可调用线索 | A 股覆盖与时效线索 | 公开可确认的商业展示/再分发权 | 是否适合作为主数据源 |
| --- | --- | --- | --- | --- |
| **Wind** | 官方 Client API；支持 Python、MATLAB、R、C++、C#、VBA | 官方列示中港美公司与行业数据、快速多资产行情、历史日线/Tick/分钟数据 | 未在公开介绍页确认本项目所需的用户端展示、归档和再分发；需合同 | **首选候选**：先走企业询价、授权和 POC |
| **Choice** | 官方用户指南列出量化接口 API，支持多语言、多系统 | 覆盖沪深京、港交所及海外交易所的基本资料、行情、财报、估值、资讯等 | 公开指南未确认向受邀用户展示衍生报告/再分发的权限；需合同 | **强备选**：与 Wind 同时询价/POC |
| **iFinD** | 官方数据接口页明确可用于构建新系统或与已有系统集成 | 官方列出股票等品种的高频序列和全球主流交易所实时行情、2000+ 标准化报表 | 公开页未确认用户端展示、归档和再分发；需合同 | **强备选**：与 Wind、Choice 同时询价/POC |
| **Fin/亿信开放平台** | X-API-KEY；`fin-db` 与 `search` 具备机器可读 OpenAPI | `fin-db` 可面向 A 股财务行情、海外财务行情、宏观行业库自然语言问数 | 未发现公开授权条款证明研究报告可面对受邀用户展示、归档或再分发 | **不做主行情源**；可作为待授权的研究证据补充 |
| **Tushare** | 官方支持 HTTP、SDK 等调用 | 有 A 股相关接口与付费数据服务 | 服务协议写明个人、不可转让、非商业、仅个人查看；常规账户不符合本项目 | **不采用**；除非另签企业商业合同 |
| **AKShare** | Python 库及 AKTools HTTP 工具 | 聚合大量公开源，接口随上游站点变化需维护 | 官方声明数据仅用于学术研究，并提示部分接口可能移除 | **不采用**；最多用于本地开发/交叉核验 |
| **TdxClaw/通达信 SkillHub** | 可安装技能提示；TdxClaw 内置技能存在 | 面向客户端使用；公开页不构成云端 API 合同 | 内置技能明确只能在 TdxClaw 客户端内部使用 | **不采用**为云端主源；可作为人工研究工具 |
| **Finnhub** | 标准 REST API、SDK、实时/历史美国及部分国际数据 | 官方公开套餐重点为美股和少数海外市场，非 A 股主覆盖 | 公开套餐均标注 Personal Use；企业页才单列 Commercial use/Redistribution right | **不采用**为 A 股主源；仅可作为早盘海外信息候选，且需企业授权 |

## 4. 各平台依据与判断

### 4.1 Wind（万得）：首选候选

- 官方 Client API 页面说明 API 可供内部或第三方应用访问数据；支持公司与行业分析、宏观研究、风险监控等场景，并列出 Python、MATLAB、R、C++、C#、VBA。[Wind Client API](https://www.wind.com.cn/mobile/ClientApi/zh.html)
- 同一页面列出全资产类别快速行情、历史日线/Tick/分钟数据回放、全球宏观和行业指标，并说明有专业数据处理与运维能力。它最符合“事实数据 + 报告所需的稳定历史口径”的需求。[Wind Client API](https://www.wind.com.cn/mobile/ClientApi/zh.html)
- Wind 的数据服务页面还列出 API、FTP、Filesync 和网页组件等交付方式；其实时行情页面说明其为交易所授权的行情转发信息商。具体 A 股等级、延时和页面展示权仍需合同确认。[Wind 数据服务](https://www.wind.com.cn/portal/zh/Home/)；[Wind 实时行情服务](https://www.wind.com.cn/portal/zh/WDS/marketdata.html)
- Wind 的 AI 金融能力市场还公开描述了可供智能体获取结构化市场、财务、宏观数据的能力；这说明它有面向程序化/智能体集成的产品方向，但不等于自动获得对外发布权。[Wind AIFin Market](https://aifinmarket.wind.com.cn/)

**判断：**若预算允许，优先询价。要求销售在合同或书面邮件中逐项确认：云端服务端 API、A 股实时/延时等级、日终数据完成时间、允许对 5–10 名受邀用户展示的衍生图表/文字、来源标识、历史归档、并发/调用配额、SLA、故障补偿及数据订正机制。

### 4.2 东方财富 Choice：强商业备选

- Choice 官方用户指南说明其量化 API 以函数调用方式提供股票、基金、债券、指数、期货、期权、外汇等品种的数据，覆盖沪深京交易所等，并支持 Python、Java、C++、R 等多语言/多操作系统。[Choice 智能金融终端用户指南](https://choice.eastmoney.com/choicewebfile/UserGuide.pdf)
- 官方指南列出基本资料、行情、财报、估值、资讯等数据类型，适配本项目 A 股复盘和行业数据的主要结构化需求。[Choice 智能金融终端用户指南](https://choice.eastmoney.com/choicewebfile/UserGuide.pdf)
- Choice 面向个人用户的公开协议明确为个人、非商业用途，商业复制、发表等需书面授权；企业采购合同必须明确覆盖本项目场景。[Choice 用户协议](https://choice.eastmoney.com/html/userprotocol/userprotocol.html)

**判断：**应与 Wind 并行询价。尤其要确认其 API 是否允许部署在 Vercel/云端后端，及对受邀用户的研究报告展示、缓存和历史归档权利。

### 4.3 同花顺 iFinD：强商业备选

- 同花顺官方数据接口页面说明接口可用于构建新系统或与已有系统集成；列出基础数据、高频序列、实时行情、快照数据及 2000+ 标准化报表。[同花顺数据接口](https://quantapi.10jqka.com.cn/gwstatic/static/ds_web/quantapi-web/)
- 页面写明高频序列包含日内和历史分钟 K 线，实时行情覆盖全球主流交易所，技术能力上满足午盘扫描与日终复盘的候选条件。[同花顺数据接口](https://quantapi.10jqka.com.cn/gwstatic/static/ds_web/quantapi-web/)
- 官方 FAQ 提示收盘后数据库入库通常需 1–2 小时，逐笔数据需另购 DataFeed；因此午盘所需实时等级及其价格要在合同里单独写清。[iFinD 数据接口 FAQ](https://quantapi.10jqka.com.cn/gwstatic/static/ds_web/quantapi-web/help-center/faq.html)

**判断：**应与 Wind、Choice 同时比较。重点不是“接口能否调用”，而是确认 A 股实时权限、数据订正、云端部署方式、对外展示和历史留存的许可边界。

### 4.4 Fin/亿信开放平台：研究证据补充候选，不是主行情源

- 官方 `fin-db` OpenAPI 说明它对 A 股/海外财务行情数据库和宏观行业数据库做自然语言问数；调用方需解析 `result[].content` 中的 Markdown 文本，并建议复杂查询设置较长超时、对 `429` 做配额处理。[fin-db API](https://openapi.billionsintelligence.com/docs/fin-db)
- 官方 `search` OpenAPI 支持网页、公告、研报、专家等检索源，结果中有标题、外链、摘要和可能为空的日期；因此适合“找线索和来源链接”，但不应把日期粒度不完整的检索结果伪装成精确行情时间戳。[search OpenAPI](https://openapi.billionsintelligence.com/.well-known/openapi/search.json)
- 官方 `fetch` 文档说明它可获取公开 URL 的正文；原始网页与研报的权利仍由上游内容方决定。平台接口能力不自动授予二次展示、全文存档或再分发的权利。[fetch API](https://openapi.billionsintelligence.com/docs/fetch)

**判断：**它非常适合未来的公告/新闻/研报线索补充和多源交叉验证；但 `fin-db` 是自然语言结果，不是带逐字段时间戳、交易所级别口径和稳定可审计 schema 的主行情接口。获得书面授权前，不进入正式报告链路。

### 4.5 Tushare：常规账号不合格

- Tushare 的公开服务协议说明有基础、特色、增强和高成本付费数据服务。[Tushare 数据服务协议](https://tushare.pro/document/1?doc_id=405)
- 但该协议同时明确服务是个人、不可转让、非商业、仅个人查看的许可，并禁止以营利或经营等非个人目的开通服务。它还声明不能保证数据的准确性、完整性和及时性。[Tushare 数据服务协议](https://tushare.pro/document/1?doc_id=405)

**判断：**不能用普通账号/积分/Token 给受邀用户的应用供数。只有在 Tushare 另行提供明确的企业商业许可、展示权、留存权和 SLA 时，才可重新评估。

### 4.6 AKShare：开发和交叉核验，不做正式源

- AKShare 官方仓库是 MIT 开源代码，但其自身声明数据仅用于学术研究，并提示部分数据接口可能因不可控因素移除。[AKShare 官方仓库](https://github.com/akfamily/akshare)
- 官方介绍页也说明其从公开网站采集数据，上游网页格式变化需要持续维护，接口稳定性受上游影响。[AKShare 项目介绍](https://github.com/akfamily/akshare/blob/main/docs/introduction.md)

**判断：**可在不进入生产的本地开发场景做样例、原型和交叉核验；不应成为需要稳定、付费可追责服务的主数据源。

### 4.7 TdxClaw/通达信：本地人工研究工具，不是云端数据服务

- 通达信 SkillHub 明确说明，TdxClaw 内置技能只能在 TdxClaw 客户端内部使用。[TDX SkillHub](https://www.tdx.com.cn/skillhub/)

**判断：**不能把技能当成报告引擎的云端供应商 API。若未来想采购通达信机构数据或行情服务，应另向通达信确认企业 API、实时授权和对外展示条款；本研究没有发现可直接替代该合同的公开授权材料。

### 4.8 Finnhub：海外早盘候选，不是 A 股主源

- Finnhub 的公开市场数据套餐页面列出的国际市场重点为 TSX、LSE、Euronext、Deutsche Börse 等，非 A 股主覆盖；各公开套餐 License 标为 Personal Use。[Finnhub 市场数据定价](https://www.finnhub.io/pricing-stock-api-market-data)
- 其企业页面单列 Commercial use 和 Redistribution right，说明普通套餐与对外再分发权不是同一件事。[Finnhub Enterprise](https://finnhub.io/pricing-startups-and-enterprise)

**判断：**不适合承担 A 股午盘/收盘事实数据。早盘的美股、期货与海外资讯可在未来作为独立候选，但仍要取得匹配使用方式的企业授权。

## 5. 推荐采购与验证路径

### 路径 A：企业级主数据源 + 研究证据补充（推荐）

1. 向 Wind、Choice、iFinD 发出同一份 RFP（见下一节）。
2. 选择一家满足“服务端 API + 对受邀用户展示衍生报告 + 归档 + 明确实时等级 + SLA”的供应商作为 A 股主数据源。
3. 只把该供应商的结构化事实用于午盘扫描、日终复盘和行业量化指标。
4. Fin 仅在授权后作为公告、研报、新闻线索与外链发现的补充；每条进入报告的事实仍需通过主源或可展示的原始来源核验。

**优点：**来源链清楚、时效可合同化、长期维护最稳。  
**成本：**采购门槛与年费更高，需要商务确认。

### 路径 B：先用 Tushare/AKShare 低成本跑通（不推荐）

技术上更快，但当前公开许可和稳定性都不满足用户端研究报告。即使只邀请 5–10 人，也属于向他人提供服务，不应把“人数少”理解成个人使用。

## 6. 统一 RFP/合同确认清单

在采购前，向每家候选供应商书面确认下列项目；任一关键项不明确，就不能进入正式接入：

1. **使用主体与场景**：知行是非个人化市场研究 Web 应用；灰度期仅 5–10 名受邀用户；不交易、不下单、不提供个性化投资建议。
2. **技术部署**：是否允许后端服务端/云端 API 调用；是否限制为桌面终端、本地 SDK、IP 白名单或特定运行环境。
3. **行情等级**：A 股指数、个股、行业、资金和公告的实时/延时等级、日终落库时间、交易日历和复权/订正规则。
4. **展示权**：是否允许在登录后的 Web 页面展示基于原始数据加工的文字、图表、汇总指标和风险提示；是否要求数据源标识。
5. **留存权**：是否允许保存报告、关键字段、数据截至时间、来源和版本，用于历史归档、审计与纠错；保留期限和删除义务是什么。
6. **再分发边界**：是否禁止展示原始逐笔/Level-2/完整数据表；哪些字段可展示；是否有用户数量、地域或设备限制。
7. **可靠性**：SLA、支持响应时间、故障通知、补数/订正机制、配额、限流和灾备。
8. **价格与扩展**：灰度期价格、后续用户增长阶梯、实时行情附加费、海外早盘数据是否需要单独购买。
9. **合规材料**：合同主体、数据来源声明、授权范围、审计支持和书面确认联系人。

## 7. 最终决策规则

在合同和 POC 都完成前，项目中的数据源状态只能是 `candidate`，不能写入任何生产密钥或真实数据接入代码。

建议采用下列优先级做最终打分：

1. 合同是否明确允许本项目的服务端调用、受邀用户展示和归档；
2. A 股盘中数据是否为所需实时等级，且有明确 SLA；
3. 日终、公告、行业和基本面的口径与订正机制是否可审计；
4. API 是否可在可信云端稳定运行，并支持超时、限流、故障重试和幂等；
5. 成本是否匹配灰度期与后续扩容。

如果 Wind、Choice、iFinD 三者中只有一家能在书面合同里完整满足前两项，直接选该家；如果多家满足，再以 POC 的真实时延、字段完整性、订正追踪和总成本决定。若没有任何一家提供相应授权，则保持离线样例模式，不能绕过许可使用免费/个人 Token。

## 8. 本轮边界

- 未创建、索取、发送或保存任何 API Key。
- 未调用任何需要认证的供应商接口，未下载或保存真实市场数据。
- 未改动报告引擎、调度、部署、Supabase 或 Coze 相关实现。
- 本文件是下一阶段“数据源授权与正式 API 契约设计”的输入，不代表已批准接入。
