# 工作教训

## 多岗位任务分发
- 错误：把主任务内部不可见的临时子 Agent 当成 StarWork 侧边栏长期岗位，导致用户在既有岗位对话里看不到任务和交接。
- 正确：优先使用既有侧边栏岗位任务进行分发和持续交接；临时子 Agent 只能作为内部辅助，并应向用户明确说明其不可见性。

## 长需求访谈的岗位同步
- 错误：在关键问题尚未问完时，把每个单独答案逐条同步给其他岗位，造成重复消息和上下文消耗。
- 正确：先在主对话集中问完关键问题并整理成结论文档，交用户审阅后，再把完整结论一次性分发给相关岗位。

## UI/UX 页面决策的确认方式
- 错误：把同一个页面的多个设计问题拆成连续的单项 A/B/C 提问，用户难以看到整体关系，也难以把文字选择与页面效果对应起来。
- 正确：每个页面先生成一份集中决策表，统一列出备选项、推荐项和理由；同时生成基于推荐项的 UI 预览供对照。用户一次反馈，新衍生问题另建补充表，确认后再固化正式页面资产。

## 推荐项与已确认选择必须显式区分
- 错误：生成“全部采用推荐项”的预览时，文案容易让用户误以为 AI 已替用户完成选择，跳过了确认环节。
- 正确：初始决策表必须保留“待填写”，预览显著标注“推荐草案、尚未确认”；只有用户明确确认后，才能把选择写回、生成正式资产并更新索引。

## 集中决策表必须沿用项目固定格式
- 错误：把后续集中决策改成新的长列表样式，导致用户难以按统一位置比较 A/B/C、推荐理由和自己的选择。
- 正确：本项目的集中决策表固定使用“编号 / 需要确认的问题 / A / B / C / 推荐 / 你的选择或意见”七列；新问题可另建补充表，但不得擅自更换表格结构。
