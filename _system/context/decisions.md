# 关键决策

## 2026-08-03 - 客户端工程与 Git 安全参数全部采用推荐方案

用户确认项目根采用单一 Git 仓库，先完成本地安全基线再连接私有 GitHub；所有环境文件、签名材料、Android 本机配置和运行缓存必须忽略。客户端固定使用 `client-app/`、React + TypeScript + Vite、Capacitor 8、Hash 路由和 `com.zhixing.research`，Android 参数为 `minSdk 24 / compileSdk 36 / targetSdk 36`；第一切片只使用去敏固定样例并构建调试 APK。

## 2026-08-03 - 品牌视觉基础采用“深海蓝研究院”

App 图标使用不带文字的“折页与路径”自适应图标；启动页采用浅灰白背景、居中图标、“知行”和“个人市场研究”，首版仅浅色主题。主色、字体、字号、间距、圆角、阴影、描边、状态色和动效使用一套统一 Token，工程实现不得借视觉统一改变已确认的信息架构。

## 2026-08-03 - 页面级 UI/UX 总稿批准，品牌视觉基础后置单独确认

用户已确认页面级 UI/UX 总稿：九个客户端页面、四项底部导航、研究子层级及正常/加载/空/失败/离线/旧内容叠加状态均可作为工程参考。App 图标、启动页和统一设计 Token 尚未确认，因此当前只批准页面与状态，不据此初始化客户端工程；下一步先完成品牌视觉基础，再处理 Git、安全与 Android 工程参数。

## 2026-08-02 - UI/UX 改为“集中决策表 + 推荐预览”双轨确认

同一个页面需要确认的问题不再逐条零散询问，而是集中整理为包含 A/B/C、推荐项、理由和用户意见栏的决策表；同时按推荐项生成临时 UI 预览，用户对照表格和界面一次性反馈。新问题另建补充表，页面确认后再固化正式 HTML、PNG 和索引记录。

## 2026-08-02 - 客户端阅读与研究信息架构完成阶段性确认

底部导航采用“今日、报告库、研究、我的”；研究页顶部采用“总览、行业、标的池”。首页采用阅读优先 B2，报告库采用统一时间流与筛选，报告详情采用沉浸式阅读；行业详情按“当前趋势、正反证据、30 天状态时间线、当前标的与变更、专项报告”组织，并在证据不足时失败关闭，不沿用旧判断冒充当前判断。

## 2026-08-02 - 先完成地基清理和客户端 UI/UX，再初始化 Android 工程

当前先同步项目本地工作系统、辅助导航和多岗位交接状态，然后集中确认客户端关键问题并形成完整 UI/UX 规格。用户确认设计前，不初始化 Git、Capacitor 或 Android 工程，不安装工具链，也不修改报告引擎。

## 2026-08-01 - 产品路线改为个人 Android APK

“知行”第一版仅供项目所有者本人使用，以 Capacitor 打包的 Android APK 交付。保留今日报告、报告库、报告详情、行业与核心关注标的池、PDF 和个人操作页；不开放朋友注册、共享阅读、订阅、通知中心、收费或运营体系。

## 2026-08-01 - APK 与生产报告引擎职责分离

APK 是可视化客户端，未来通过受保护应用 API 读取可信云端报告引擎生成和归档的内容。真实数据凭证、模型凭证、调度与私有存储只允许存在于可信服务端；Codex 不需要持续在线，APK 也不得内置这些密钥。

## 2026-08-01 - iFind 仅作为后续个人数据源候选

iFind 个人产品被记录为未来候选，但尚未验证能否用于可信云端定时任务、具体接口、字段、时效、配额和凭证方式。当前不得把候选方向描述为已接入能力，也不得配置真实密钥或真实数据。

## 2026-07-31 - 历史决定：企业级数据源并行询价（已被个人 APK 路线覆盖）

该决定记录了此前受邀用户 Web 应用阶段的企业级选型结论。2026-08-01 起项目已改为个人 APK，当前不再执行 Wind、iFinD、Choice 并行询价任务；其中对真实数据可靠性、凭证隔离和失败关闭的原则继续保留。

## 2026-07-31 - 行业跟踪采用单报告、混合关注单元与双层输出

`industry_tracking` 未来每个 A 股实际交易日只生成一份，覆盖全部固定核心关注单元和每日最多 3 个特别关注单元；特别关注由上游显式提供、每日重评、可为空。报告同时输出可归档比较的结构化数据和复用共享视觉模板的受控 HTML，灰度期先由管理员审核发布。

## 2026-07-31 - 关注赛道与申万一级行业标签分离

交接文档中的 16 个“十五五”赛道只作为候选关注单元，不直接等同于申万一级行业。每个关注单元使用稳定 `focusId` 和 `displayName`，映射一个或多个申万一级 `industryTags` 及可选 `themeTags`；趋势主要依据当期与对比期数据，历史报告只用于审计复核。

## 2026-07-30 - 多岗位任务优先分发到侧边栏长期 Agent

包含两个及以上可独立验收子任务的工作，由主对话拆分后优先发送给已建立的“报告引擎开发”“规格与验收”“安全与质量审查”“任务协调与交接”侧边栏长期岗位。主任务内部临时子 Agent 只作为辅助，不得替代可见、可持续交接的正式岗位；主对话继续负责边界、冲突、用户确认和最终交付。

## 2026-07-30 - 项目存档只写项目本地工作系统

用户调用 `$save` 或要求存档时，只更新 `D:\Codex\投顾APP\_system`。不得把本项目状态同步到 `D:\Codex\AI工作系统`；找不到项目本地 `_system` 时失败关闭，不使用全局目录兜底。

## 2026-07-30 - 三端报告使用共享语义 HTML

早盘、午间与每日复盘采用同一份语义 HTML：桌面端保留表格，手机端自动转换为逐条信息卡，PDF 使用 A4 打印样式。保留深蓝表头和浅色阅读布局，但不迁入仓位、持仓、止损或买卖指令等交易性内容。

## 2026-07-29 - 午间复盘采用结构化前序判断验证

`midday_review` 只接收调用方内联传入的同日早盘与此前复盘判断记录，不读取文件或历史运行结果；缺失或不可追溯时失败关闭，以保持离线原型可审计。

## 2026-07-29 - 内容合规按一次 HTML 实体解析并覆盖输出契约

数值字符实体（十进制、十六进制、分号可选）按浏览器一次解析语义纳入合规检查；不二次解码。`priorAssessments.originalJudgement` 也必须接受同一非个人化与交易指令校验，避免生成路径与输出校验器不一致。
