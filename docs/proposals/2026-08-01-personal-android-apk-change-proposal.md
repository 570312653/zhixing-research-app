# 知行：个人 Android APK 客户端变更报告（已确认）

> 状态：**已确认并同步正式文档**  
> 日期：2026-08-01  
> 确认日期：2026-08-01  
> 目的：记录从“受邀用户 Web 应用”调整为“个人专属 Android APK 客户端”的影响。本次确认已经同步到正式需求、架构和当前状态文档；仍不代表 Android 工程、云端能力或真实数据已经实现。

## 1. 拟确认的产品目标

知行调整为仅供项目所有者本人使用的移动端市场研究工具：

- 手机端以 Android APK 安装包交付，而非仅通过浏览器访问；
- 手机客户端用于阅读、分类、检索和管理个人报告；
- 云端报告引擎负责定时生成、校验、归档和提供受保护的数据接口；
- Codex 只参与开发、测试和维护，不承担生产定时运行；
- 不开放朋友注册、邀请、订阅、多人阅读、运营统计或对外分享；
- 报告仍是非个人化市场研究，不输出买卖、仓位、止损、收益承诺或个性化投资建议。

这不是“只有报告引擎”的项目：APK 是完整可视化客户端；报告引擎是后台生产系统。

## 2. 推荐实现路线

### 方案 A：Capacitor 混合 APK（推荐）

```text
Android 手机上的「知行」APK
  └─ Capacitor 原生外壳 + 既有 Web 界面
       └─ 受保护的应用 API
            └─ 知行报告引擎（可信云端运行时）
                 └─ 数据源适配器 → 结构化证据 → 报告 / HTML / PDF
```

- 复用 Web 技术栈和已经完成的响应式报告视觉模板；
- 通过 Capacitor 打包为可安装的 Android APK，桌面有“知行”图标；
- 后台、定时生成、私有存储和密钥仍在云端，APK 不保存数据源密钥；
- 后续如需要 iOS，可复用大部分界面代码；
- 代价是首次需要配置 Android SDK、签名证书和 APK 更新流程。

### 方案 B：原生 Android（Kotlin/Flutter）

- 体验和系统能力最强；
- 需要独立重写界面和状态管理，开发、测试和后续维护成本明显更高；
- 当前没有必须依赖原生能力的需求，因此不推荐作为第一版。

### 不采用：PWA 作为第一版交付形态

PWA 仍可保留为电脑端/应急访问入口，但不作为本轮主要交付。用户已明确希望获得 APK，因此它不能替代 Android 安装包。

## 3. 安装、更新与手机使用方式

### 首次安装

1. 部署一个 HTTPS 下载页，生成对应二维码；
2. 用户扫码进入下载页，下载已签名的 APK；
3. Android 按系统提示允许本次来源安装应用；
4. 安装后桌面出现“知行”图标，像普通 App 一样打开。

二维码只负责打开下载页，不承载报告数据、密码或数据源密钥。

### 版本更新

- 每个 APK 使用固定签名证书；
- 发布新版时提高应用版本号；
- 用户从同一下载页获取新版 APK，由 Android 覆盖安装；
- 签名证书必须离线备份，丢失后不能直接覆盖更新既有安装包；
- 第一版不接入应用商店、不做自动更新和不做 iOS 安装包。

## 4. 第一版手机客户端范围

### 包含

1. **今日报告**：早盘、午盘、复盘、行业跟踪的当日状态与入口；
2. **报告库**：按日期、报告类型、行业/主题分类与检索；
3. **报告详情**：沿用已确认的阅读样式，展示版本、数据截至时间、风险提示；
4. **产业与标的池**：行业跟踪与核心关注标的的分类、历史变化和筛选；
5. **PDF**：报告 HTML 生成成功后提供 PDF 下载；PDF 失败不得覆盖已归档的 HTML 报告；
6. **个人操作页**：查看生成状态、手动请求重试已失败任务、刷新内容与查看应用版本。

### 暂不包含

- 注册、邀请、多人账号、订阅偏好、邮件、站内通知中心、收费或支付；
- 对外公开链接、社交分享、评论或社区；
- 行情大屏、实时交易终端、自动交易；
- iOS 安装包；
- 在手机客户端中展示或编辑数据源密钥、模型密钥、原始数据抓取内容。

## 5. 权限、存储与运行架构变化

| 领域 | 原 Web 应用设想 | 拟调整后的个人 APK 方案 |
|---|---|---|
| 访问对象 | 受邀用户 | 单一所有者 |
| 登录 | 邮箱 Magic Link、多用户 RLS | 单一所有者账户；仍需服务端鉴权，不能依赖“APK 私有” |
| 报告可见性 | 已发布给受邀用户 | 仅所有者账户可读取 |
| 用户统计 | 阅读率、灰度反馈等 | 仅保留任务运行、失败、版本和设备诊断所需的最小日志 |
| 客户端 | 响应式 Web / PWA | Capacitor 打包的 Android APK；可保留 Web 预览入口 |
| 调度 | 可信云端 | 不变，仍由可信云端执行，不能依赖 Codex 在线 |
| 凭证 | 服务端环境变量 | 不变；绝不写入 APK、前端、日志或二维码 |

即使是个人应用，也必须通过服务端验证所有者身份。APK 文件可以被复制，不能把“只有我安装”当作权限控制。

## 6. 数据源与报告引擎的影响

- 用户希望将 iFind 作为个人报告引擎的主要数据候选；本提案只记录该产品方向，**不代表已完成数据接口、运行方式、字段、时效或凭证验证**。
- iFind 的密钥或个人凭证不得进入 APK；若未来接入，只能在可信云端的受控环境变量中使用。
- 在实际接入前，必须单独完成“数据适配器契约”设计：交易日历、字段映射、数据时间、调用配额、错误分类、证据留存与失败关闭规则。
- iFind MCP 是否能以适合云端定时任务的方式被稳定调用，尚未验证；不能仅因手机端需要 APK 就假定该能力已经存在。
- 数据不足、数据时间不符合要求或适配器调用失败时，报告引擎必须失败关闭并记录原因，不能编造市场事实。
