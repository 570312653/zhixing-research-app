# “今日报告”已确认决策稿 v1

> 用途：汇总“今日报告”首页在多轮视觉讨论中已经确认的布局、内容顺序和动态区域规则。  
> 状态：2026-08-02 已确认；本文件只整理既有结论，不新增产品能力。  
> 当前阶段：正式页面仍使用固定样例，不代表真实报告、任务状态或云端同步已经接入。

## 一、页面目标

首页首先服务于快速阅读，而不是展示后台任务监控。用户进入应用后，应能先继续上次未完成的阅读，或直接进入当前最新报告；任务异常和运行诊断留在具体报告卡片及“我的”页面中呈现。

## 二、已确认规则

| 编号 | 决策项 | 最终结论 |
|---|---|---|
| 1 | 总体布局 | 采用 **B2：纯阅读优先**，不在首页顶部放任务进度或异常总览条 |
| 2 | 主阅读卡 | 优先提供“继续阅读”入口；没有未完成阅读时展示最新已生成报告 |
| 3 | 核心摘要 | 只汇总当日已经生成的报告，不为尚未生成或失败的报告补写摘要 |
| 4 | 日常报告顺序 | 固定为早盘扫描、午间复盘、每日复盘、行业跟踪，保持每日位置稳定 |
| 5 | 日常卡片信息 | 展示报告名称、计划/发布时间、数据截至时间、版本、阅读状态及必要的延迟/失败状态 |
| 6 | 异常呈现 | 不在首页顶部集中强调异常；延迟、失败或未到时间在对应卡片中显示，完整任务恢复入口进入“我的” |
| 7 | 周期报告位置 | 放在四个日常报告下方的独立动态区域；周末、节假日及月末报告生成后在这里出现 |
| 8 | 周期报告空档期 | 没有周期报告时整块隐藏，不增加空方块，也不显示“仅有内容时出现”等解释文字 |
| 9 | 周期报告标题 | 区域标题固定为“周期报告”；最新报告卡显示类型、标题、时间和阅读状态，并进入报告详情 |
| 10 | 主导航 | 底部固定为“今日、报告库、研究、我的”，首页激活“今日” |
| 11 | 页面边界 | 不展示实时行情、收益、公开分享、订阅、成员或后台配置入口 |
| 12 | 状态规则 | 正常、加载、空、失败、离线及旧内容叠加统一遵循 `cross-page-states-v1.md` |

## 三、内容层级

```text
今日标题与日期
  → 主阅读卡（继续阅读 / 最新报告）
  → 当日已生成报告的核心摘要
  → 四个日常报告固定卡片
  → 周期报告动态区域（有内容才出现）
  → 底部主导航
```

## 四、固定样例边界

- 页面中的报告、时间、摘要和阅读状态均为用于验收布局的固定样例。
- 尚未接入报告 API、真实任务、所有者认证、云端同步或 PDF 下载。
- 未到时间、失败或离线时不得用固定样例冒充正式内容；实现时必须使用已确认的跨页面状态规范。

## 五、实现验收重点

- 390px 宽度无横向滚动，主阅读卡和摘要在首屏形成清晰阅读入口。
- 四个日常报告位置稳定，周期报告出现或隐藏时不破坏日常区域布局。
- 周期报告区域不显示“仅有内容时出现”等面向设计者的说明文字。
- 首页没有后台监控感；异常可发现但不抢占主要阅读层级。
- 所有卡片可以映射到统一报告详情路由和报告状态模型。
