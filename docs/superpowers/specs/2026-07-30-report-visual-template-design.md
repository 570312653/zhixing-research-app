# 知行报告视觉模板设计

> 状态：已确认；本文件只定义视觉与版式，不定义真实市场数据、事实结论或报告生成逻辑。
>
> 日期：2026-07-30

## 1. 目标与范围

以现有《每日早盘扫描报告 v2.2》和《每日复盘报告》PDF 为视觉基线，建立一套可同时服务桌面网页、手机网页与 A4 PDF 导出的报告模板规范。

本设计覆盖三种展示模板：

- `morning_scan`：紧凑的盘前信息版。
- `midday_review`：紧凑的盘中观察版，视觉上参考早盘扫描。
- `daily_review`：可承载较长文本与多张数据表的深度复盘版。

本设计不授权接入真实数据、数据源、模型、网络、PDF 渲染器、云端服务或定时任务；也不冻结各栏目中的真实数据字段和研究结论。

## 2. 设计决策

### 2.1 单一语义 HTML，三端自适应

报告使用同一份语义化 HTML 内容树，由 CSS 分别呈现为：

```text
桌面网页：完整宽表格与分栏阅读
手机网页：数据表转为逐条信息卡片
A4 PDF：保留宽表格、页眉、页脚和页码
```

不为网页和 PDF 维护两套正文模板。这样可以避免同一报告在不同端的标题、摘要、来源或风险提示发生漂移。

### 2.2 信息与交易边界

沿用原 PDF 的信息密度、表格节奏、警示色和重要性标记，但正式模板不得出现或要求生成：

- 清仓、加仓、减仓、止损、仓位比例、持仓处理等操作指令。
- 面向某一用户的持仓、盈亏、账户或收益判断。
- 收益承诺、确定性涨跌预测或个性化投资建议。

红、黄、绿和星级只能表达公开信息的风险等级、重要性、观察状态或验证状态；必须配套文字标签，不能只依赖颜色。

## 3. 视觉令牌

以下令牌依据参考 PDF 的主视觉提取；实现时统一使用，避免每个报告自行配色。

| 用途 | 令牌 | 初始值 | 规则 |
|---|---|---|---|
| 主色/表头/一级分隔线 | `brand-navy` | `#1E3A8A` | 深蓝背景配白色文字。 |
| 正文主文字 | `text-primary` | `#1F2937` | 保证长文阅读对比度。 |
| 次级文字/元数据 | `text-muted` | `#6B7280` | 用于时间、来源、页脚。 |
| 页面底色 | `surface-page` | `#FFFFFF` | 保持浅色、专业、阅读优先。 |
| 表格斑马行 | `surface-subtle` | `#F3F4F6` | 只作行区分，不喧宾夺主。 |
| 正向/已验证 | `signal-positive` | `#15803D` | 必须同时显示“已验证”等文字。 |
| 观察/待验证 | `signal-watch` | `#B45309` | 必须同时显示“待验证”等文字。 |
| 风险/失效 | `signal-risk` | `#B91C1C` | 必须同时显示“风险/失效”等文字。 |
| 风险提示底色 | `surface-risk` | `#FDE8E8` | 仅作固定风险提示或高风险事实的弱强调。 |

字体优先使用系统中文无衬线字体：`PingFang SC`、`Microsoft YaHei`、`Noto Sans CJK SC`、`sans-serif`。不把 emoji 作为唯一状态标记；PDF 中的星级可使用文本 `★`，同时提供“高/中/低重要性”文字。

## 4. 通用页面骨架

所有模板按以下顺序组织；具体报告可省略空的可选区块，但不能隐藏元数据或风险提示。

1. **页眉**：品牌名“知行”、报告类型、报告日期、版本号。
2. **元数据行**：数据截至时间、生成时间、公开来源说明；来源不足时明确标为“来源待补充”，不得编造。
3. **标题与摘要区**：主标题、1 条中性概览，以及可选的 3～5 条摘要卡片。
4. **编号章节**：使用“一、二、三……”的一级标题；同级标题使用相同的深蓝分隔线和留白。
5. **结构化信息块**：表格、摘要卡、来源/验证状态或风险提示。
6. **固定风险提示**：正文末尾原样显示“仅供信息参考，不构成投资建议”。
7. **页脚**：品牌、生成时间、页码；网页端不显示页码，PDF 端必须显示“第 X 页 / 共 Y 页”。

桌面正文最大阅读宽度为 1120px；长篇复盘采用单列正文，表格允许占满内容区。页面内不使用大面积装饰背景、行情大屏或连续炫彩渐变。

## 5. 可复用视觉组件

### 5.1 标题和章节

- 报告主标题使用 28–32px（PDF 约 20–22pt）粗体；副元数据使用 12–14px。
- 一级章节标题使用 20–24px，前置中文编号，并在下方放置 2px `brand-navy` 分隔线。
- 二级标题使用 16–18px，不再重复使用粗重背景条，避免长报告视觉疲劳。
- 段落行高 1.7–1.85；章节之间桌面留白 28–36px，手机留白 20–24px。

### 5.2 概览与提示卡

- 概览卡采用浅灰或低饱和背景，左侧用状态色细边，不以整块高饱和颜色占据页面。
- 风险提示使用浅红底、风险图标和固定文案；图标是辅助，不替代文字。
- 重要性星级在卡片或表格中左对齐显示，旁边必须有状态说明。

### 5.3 数据表

- 桌面与 PDF：表头为 `brand-navy` 白字；表体使用白底与浅灰斑马行；数值列右对齐，文字列左对齐。
- 表头不得只写模糊缩写；单位要在列名或首行清楚标明。
- 单元格使用 10–12px（PDF 约 8–9pt）文字，行高至少 1.45；超长文本允许换行，禁止截断关键信息。
- 来源、状态与风险字段应保留为独立列或附带清晰标签，不能藏在颜色中。

### 5.4 手机表格转卡片

当可用宽度小于 768px 时，复杂表格转为“字段标签 + 值”的纵向信息卡：

```text
[ 状态标签 ]  条目名称
关键字段：值
辅助字段：值
来源/备注：值
```

- 卡片按原表格行顺序排列，字段名不丢失。
- 同一组内最多突出 1 个主字段，其他字段使用次级文字。
- 长链接显示为来源标题，不直接展示完整 URL；点击后才跳转。
- 简单的两列表可保留为表格，但必须可横向完整阅读，不能裁切列。

## 6. 三种模板的版式约束

| 模板 | 桌面/网页目标 | PDF 目标 | 手机目标 |
|---|---|---|---|
| `morning_scan` | 盘前快速阅读，摘要和关键表格优先 | 参考现有早盘 4 页的紧凑密度 | 概览优先，表格转卡片，章节可折叠 |
| `midday_review` | 作为早盘的中间检查点，视觉密度不高于早盘 | 原则上短于早盘；必要时自然分页 | 保持单列，突出“前序判断验证”状态 |
| `daily_review` | 长文、分层文本和多张数据表并存 | 参考现有复盘的多页结构与页脚 | 章节单列展开，表格全部转卡片 |

各模板的实际栏目名称、指标、数据来源与内容长度，等数据源和内容标准确认后另行决定；本文件不把示例 PDF 的具体栏目或数值固化为生成要求。

## 7. HTML 到 PDF 的映射

HTML 是唯一正文来源。未来引入 PDF 导出时，应以浏览器打印 CSS 生成 A4 PDF，保持以下规则：

- A4 纵向，页边距 14–16mm；页面背景必须允许打印。
- 使用 `@media print` 隐藏网页导航、交互按钮、折叠控件和移动端卡片控件。
- PDF 端恢复完整表格，并让 `thead` 在跨页时重复；避免表格行、标题与其首段被不合理拆分。
- 每页保留页眉/页脚、品牌、生成时间和页码；没有 PDF 渲染器时返回明确失败状态，不能伪造下载文件。
- PDF 的视觉验收以参考 PDF 的层级、留白、表格可读性和页脚一致性为准，不以像素级复制为目标。
